What building a MERN store taught me about code structure

MERN May 2025 · 4 min read

My e-commerce project started as a structured course build: a React storefront on top of an Express API with MongoDB behind it. The catalog, cart, checkout and admin screens were the visible part. The part that actually changed how I write code was the backend's shape.

Layers, not one file

My first instinct with Express would have been one big index.js with every route defined inline. The course project wouldn't allow it. Each concern got its own folder:

backend/
  routes/        # URL to handler mapping
  controllers/   # request logic, nothing else
  models/        # Mongoose schemas and queries
  middlewares/   # auth guard, error handler
  config/        # db connection, env setup

The routes layer reads like a table of contents. When a request misbehaves, I know instantly which file to open, because each layer can only do one job.

Auth is a pipeline

Authentication stopped being mysterious once I saw it as middleware. A signup route hashes the password with bcrypt and stores the user. A login route compares hashes and issues a JWT. Then a single authMiddleware verifies the token from the cookie and attaches the user to the request:

router.get("/admin/products", authMiddleware, adminOnly, getProducts)

One line expresses "only logged-in admins reach this handler." Before building this, JWT felt like magic. After, it's just a signed string, a secret, and one function in the right place in the pipeline.

What I'd do differently

  • Validate input at the boundary. I trusted the client too much and paid for it in weird test data.
  • Image uploads (Multer) deserved their own service early on instead of living inside a controller.
  • Writing the README with setup steps as I went would have saved a painful reconstruction at the end.

Next I'm applying the same layered thinking to AI features: an LLM call is just another controller talking to an external API, and prompt templates belong in their own module, not scattered through handlers.
