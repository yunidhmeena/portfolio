Two client sites, zero frameworks

Client work September 2024 · 3 min read

Before I touched React, I got paid to write HTML. In 2024 I built and launched two production websites for business clients: a machinery company and a brokerage firm. Both were hand-written HTML, CSS and JavaScript. No framework, no build step, no dependencies.

That constraint was the point. The sites needed to load fast on entry-level Android phones, render correctly on whatever browser the client's customers happened to use, and be simple enough that I could hand over a folder the client could reasonably own.

What actually mattered

The machinery site needed one thing above everything: a way for a stranger with a broken machine to become an inquiry in the client's inbox. So the design funnels every page toward a contact form, and the form lands on a thank-you page so the client knows the flow completed. That one flow justified the whole project.

For the brokerage firm, credibility was the product. Clean typography, a layout that didn't shout, and pages that opened instantly did more for trust than any feature could.

Lessons I keep using

  • Scope shrinks in conversation, not in code. Both sites changed after the first client call.
  • "Done" means launched, not locally correct. Deployment, domains and post-launch fixes are part of the job.
  • Frameworks solve problems I didn't have. Plain CSS and a few dozen lines of JS covered layouts, forms and interactions.

Since then I've moved on to React and full stack work, but I still write CSS the way I learned to on these sites: mobile first, few breakpoints, no utility framework doing the thinking for me.
